# UI/UX review — 14 October 2026

Reviewed the current Passenger, Admin, Ticketing and Boarding implementation, navigation, shared controls, booking/payment flow, directory search, schedule management, forms and feedback. This is a review; application files and hosted records were not changed for this task.

## Evidence and limits

- Captured 212 rendered screen configurations: 53 role routes × desktop/mobile (1440/390px) × Light/Dark. Admin: 80; Passenger: 52; Ticketing: 40; Boarding: 40.
- Supabase traffic used isolated browser fixtures. No real login, payment, cash collection, booking or notification was performed.
- Inspected representative screenshots and current source. Automated checks found no captured page errors or main-content horizontal overflow. Shared button size/radius and theme checks completed. The repeated admin navigation icon check failed at both widths.
- Screenshots and structured findings: `.audit/ui-ux-20261014/`. The temporary audit runner records assertion failures instead of stopping at the first one; this review does not claim that the original regression suite passed.
- Browser timezone was deliberately America/Los_Angeles to expose inconsistencies with Philippine sailing time. The user's review date and time remain Asia/Manila.
- Public search/help/privacy smoke checking stopped on an outdated `/search` expectation: the app redirects it to `/trips`. This is a verification-script issue, not evidence of broken navigation. Public/auth screens were reviewed in source, rather than claiming a completed new public browser check.
- Did not measure production network performance, certify accessibility/contrast, test a physical Android camera, or test actual receipt printers. Fixture missing-QR messages do not establish a production QR failure.

## Improvements in priority order

| Priority | Finding and evidence | Improvement |
| --- | --- | --- |
| P1 | **Admin trip time depends on device timezone.** `AdminWorkspacePage.vue:1821` omits `Asia/Manila`; its input conversion around line 2572 uses device-local date parts. The same fixture sailing displayed midnight in the admin table and 4 PM in Boarding with the overseas test timezone. | Use one Philippine-time formatter and datetime-input conversion across viewing, creating, editing and exporting trips. Label sailing times as Philippine time. Validate midnight/overnight trips and devices outside the Philippines. |
| P1 | **Home payment guidance can mislead.** `HomePage.vue` labels an upcoming booking Payment pending and tells anyone without a ready ticket to pay at the desk. Other screens correctly distinguish online payment received from awaiting staff verification. | Make Home use the same payment/ticket state mapping as booking details. Show Pay online / Pay at counter for unpaid bookings, Awaiting verification for received payments, and View e-ticket only when ready. Include the real deadline and amount due. |
| P1 | **Important passenger actions are far down the page.** Home places SailingBoard and PortForecast before Upcoming trip. The mobile passenger-information screenshot shows header, back link, stepper, advisory and full trip card before the first input. | Put the active booking/deadline near the top of Home. Reduce the booking-step introduction and collapse secondary advisory/trip details; keep the selected route and total readily visible. Consider a sticky Continue/Review summary on small screens without covering inputs or the keyboard. |
| P1 | **Actual trip operations are below schedule templates.** `AdminWorkspacePage.vue:555` renders daily schedules before the actual trip directory. Even the empty fixture schedule block consumes most of a 390px screen; the live corridor has six templates. Boarding also places explanatory cards ahead of the arrival queue. | Separate Actual trips and Daily templates into tabs or collapsible sections. Open actual/today trips by default. In Boarding, keep the selected sailing and Find ticket action prominent and shorten the step explanation. |
| P2 | **Decision-related supporting text is too small.** TripCard status is 9px; departure date is 10px; ports and seat availability use 10–11px. Similar sizes occur in staff cards and settings. This is visible in screenshots. | Raise essential dates, statuses, fares, instructions and labels toward 13–14px, with comfortable body/control text. Keep decorative captions secondary. Check wrapping at 320/390px and larger system text sizes. |
| P2 | **Search and sort scopes differ.** Bookings/passengers/trips use server search, but RecordsGrid sorts and filters only the loaded page. Broadcast search filters `table.query` after `campaigns(page)` fetches one page; changing pages clears the search. | Use server-wide search/filter/sort for primary record discovery where paginated. Preserve query/filter state through pagination and returning from details. If an optional filter is page-local, label it explicitly. Do not report that no matching broadcast exists when only the current page was searched. |
| P2 | **Admin form errors are less actionable than passenger errors.** Port, vessel and trip errors use a shared `formError` banner; passenger forms already use `aria-invalid`, linked error text and focus handling. Trip setup can require leaving the editor to configure fares. | Apply field-specific errors and focus to the first invalid field. Add a preflight summary for route, vessel location, fares, seats and boarding configuration, with direct links to the missing setup. Preserve the draft while fixing prerequisites. |
| P2 | **Status wording still exposes internal codes.** E-ticket displays `person.ticketStatus` directly, including values such as CHECKED_IN. Booking details uses long all-caps labels such as AWAITING STAFF VERIFICATION. | Share readable status labels across roles: Ticket issued, Checked in, Boarded, Payment received—awaiting verification. Keep payment state, booking state and sailing state distinct and add one clear next action. |
| P2 | **Staff queue freshness is not visible.** Ticketing/Boarding use `useQueueRefresh`, normally every 15 seconds, without the successful-update indicator already used by AdminOverview and SailingBoard. | Show last successful update and Refreshing/Unable to refresh states for operational queues. Retain visible records on refresh failure and indicate they may be stale. Camera errors already have manual-code guidance; keep that recovery path prominent. |
| P2 | **Current records and retained history share directories.** Port and vessel lists can show inactive historical entries alongside active operational records; some were retained because existing trips/bookings reference them. | Default operational directories to active Batangas/Calapan records. Add a clearly labeled History/Archived view for inactive entries, explaining why historical identities remain. Avoid suggesting an archived vessel can be scheduled. |
| P3 | **Admin navigation repeats an icon.** Dashboard and Port Display (TV) both use `gridOutline`; the browser uniqueness check reproduced this at both widths. The shared staff back icon is now consistent, but is hidden with its wrapper at widths below 480px. | Give TV display a screen/monitor icon. Review whether the staff header should present a visible dashboard-return affordance on mobile. Preserve readable labels instead of relying on icon uniqueness alone. |
| P3 | **Desktop passenger UI remains narrow and CSS has repeated overrides.** Screenshots show a mobile-width passenger column centered in a wide desktop viewport. StaffSettingsPage has three scoped style blocks with repeated layout selectors; BookingFlow and AdminWorkspace have extensive page overrides. | Treat a wider passenger desktop layout as an optional enhancement: trip cards beside booking/forecast context while preserving mobile behavior. Consolidate shared spacing, typography, status badges, form errors and buttons to reduce future visual drift. |
| P3 | **Admin loads unrelated datasets and bundles are large.** `loadData()` requests bookings, sailings, users, ports, vessels, passengers, fares and other setup data together. The preceding successful build reported large shared chunks. | Fetch only the current module's data and needed lookup records. Cache stable port/vessel reference data and lazy-load expensive grids/charts. Measure slow-network loading before setting performance targets; bundle size alone is not a measured user delay. |

## Existing improvements to preserve

- Back controls now use one shared left-arrow component.
- Search distinguishes loading, failed load and genuinely empty results, with recovery actions.
- Passenger forms have field validation, linked errors and focus recovery.
- Walk-in payment confirmation uses a framework dialog; the older custom-overlay finding is stale.
- Mobile records have a sort control; the old claim that mobile sorting is absent is stale.
- Boarding retains the selected sailing in operation links and provides manual ticket lookup when camera use fails.
- Booking lists show booking totals; the old blanket claim that totals are absent should not be repeated.

Recommended implementation sequence: Philippine-time consistency and payment-state guidance first; then mobile task placement and readable text; then search scope, field-level recovery and queue freshness. Address shared styling and desktop expansion after those operational changes.
