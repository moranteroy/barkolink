# Mobile layout follow-up — November 4, 2026

The Android screenshots showed oversized spacing and vertically stretched passenger cards, with system bars overlaying content. Density changes now apply only to viewports at or below 600 CSS pixels. Laptop/desktop styling remains outside these media queries.

## Changes

- Compact landing navigation, hero, route cards and guide cards. Keep navigation and booking actions available.
- Reduce mobile page spacing, header and bottom-navigation height. Compact bookings, sailing board, current weather and daily forecasts without removing route/time, payment state or actions.
- Put the date and passenger count alongside each other at common phone widths; stack them below 360 px. Preserve 44 px passenger-control touch targets and prevent controls overflowing their field.
- Configure Android immersive mode with transient system bars revealed by an edge swipe. Reapply it when the activity resumes or regains focus. Reserve display-cutout insets through Capacitor, and hide passenger bottom navigation while the Android keyboard is open.
- Preserve browser zoom and Android accessibility font settings. Do not scale the entire WebView or use CSS zoom.

Implementation: `src/theme/mobile.css`, the owning landing/component mobile rules, `src/services/nativeLayout.ts`, `capacitor.config.ts`, and Android `MainActivity.java`.

## Passenger counter follow-up — November 5, 2026

The shared landing/Home counter now uses a 20 px number, 20 px plus/minus icons, and a 12 px unbroken desktop caption. On phone viewports, the visible `Passengers` field label identifies the counter and the duplicate caption underneath the number is hidden, so a narrow center column cannot split the final letter onto another line. The 44 px button targets and 1–8 passenger limits are preserved. Reusable browser checks cover singular/plural layouts, field bounds, button targets, limits, and keyboard operation in both public landing and authenticated Home fixtures.

Validation for the counter follow-up passed lint, production build/CSP, 10 landing viewport/theme checks and 72 passenger page/viewport/theme checks. Representative desktop and mobile screenshots were inspected. This follow-up has not been pushed or compiled into a new APK.
