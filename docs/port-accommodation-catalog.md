# Active ports and Starlite accommodation catalog

The admin location map previously received the complete port directory, which includes inactive historical records. Balatero was inactive in the database but still appeared as a map tab. Admin now passes only active ports. The shared map also excludes explicitly inactive ports outside a booked journey and updates its markers, selection and bounds when that list changes. An existing booking keeps its actual departure/arrival terminals even if a port is subsequently disabled.

The landing page already requests `BrowseActivePorts`; it now reloads ports when its Ionic view is entered, including a return from another page. The public endpoint selects active ports from the database. No port names are hardcoded into these visibility rules. Current active ports are Batangas and Calapan. Balatero remains an inactive directory record rather than being deleted from historical data. Source searches found no other rendered Balatero literal; the nationwide reference JSON and seed sources retain archived reference material.

Accommodation no longer exposes a nationwide operator reference panel or merges every operator's classes into its selector. The current Starlite Batangas–Calapan classes are Economy, Tourist Class and Business Class, consistent with the [official Starlite schedule/rate page](https://starliteferries.com/schedule-and-rates-2025-2/) checked October 24, 2026. The page is labelled 2025; fares and timetable values were not imported by this change.

Selecting a class fills its description, preferring the saved description for that vessel/class and otherwise using an editable class template. Opening an existing class retains its saved description. Changing capacity or surcharge does not overwrite manual description edits. Templates do not assert unverified air conditioning, bunk arrangements or other amenities.

Migration 049 normalizes `SL-SWM-STELLA-DEL-MAR` to `SL-STELLA-DEL-MAR` while retaining the vessel UUID and all sailing references. New vessel forms can generate an `SL-` code from the vessel name; the form supports 32 characters, fixing rejection of the former 21-character code. Existing codes remain read-only during normal editing. The seed generator retains the established vessel UUID when generating the normalized code.

The migration deletes unsupported Starlite classes only if no booking references them; linked unsupported classes are disabled instead. Applying it to the connected project removed five unused Premium Economy classes. Economy classes, vessel IDs, bookings, passengers and payments were preserved. The maintenance command is `node scripts/align-starlite-catalog.mjs --apply`; without `--apply` it only previews the catalog. Backup and receipt are under local `.backups/` and `.audit/starlite-catalog-alignment.json`.

Verification: 45 focused unit tests and two isolated database tests pass. Browser fixtures pass at 1440 and 390px in both themes: actual Leaflet markers, exclusion of inactive Balatero, disabling/reactivating Calapan followed by Refresh, selection recovery, public landing maps, Starlite-only class choices, automatic descriptions, manually edited description submission, and vessel-code generation. Map tiles are stubbed in these isolated browser checks; the external provider itself was not changed. Screenshots are under `.audit/service-catalog/`. Type checking, production build and security header checks pass. Full lint reports only the two existing `no-control-regex` errors in `src/data/securityValidation.ts`.
