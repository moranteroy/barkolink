# BarkoLink UI audit — October 24, 2026

Na-review ang UI ng Passenger, Admin, Ticketing, at Boarding. Unahin ang shared table behavior at mobile task placement bago ang dagdag na visual decoration. May reusable `barkolink-ui` skill sa `skills/barkolink-ui/` para consistent ang susunod na improvements.

This deliverable is an audit and reusable skill. Application UI code has not been changed.

Implementation follow-up: the subsequent UI changes are documented in [UI improvements — October 24](UI-IMPROVEMENTS-2026-10-24.md). Findings below describe the pre-change audit snapshot.

## Scope and evidence

- Inventoried the project tree, routes, dependencies, theme files, UI verification scripts, and existing audit documents. Read all 103 Vue view/component files through the source inventory pass: 22 views and 81 components. Targeted review examined role templates, grid implementation/callers, validation, status/payment helpers, ordering, and responsive styles. `App.vue`, bootstrap and router were inspected separately. Generated dependencies/builds, binaries and secrets were excluded from UI review.
- Captured **236 current rendered configurations**: 59 role routes × 1440/390px × light/dark. Admin: 26 routes; Passenger: 13; Ticketing: 10; Boarding: 10. Screenshots use an 844px viewport height. Examined representative screenshots across roles and themes; not every screenshot received individual visual inspection.
- The completed capture pass reported **0 navigation/render failures, 0 captured page/AG Grid errors, 0 visible alerts, and 0 overflowing visible `main` elements**. This is a layout smoke check, not certification of accessibility, contrast, complete content visibility, or all interactions.
- Reproduced desktop/tablet state loss with a separate real-grid interaction at 768px → 390px → 768px. Applied column visibility, sorting and filtering through the component's exposed Grid API, then inspected actual renderers and state.
- Browser sessions use existing isolated fixtures and an overseas browser timezone (`America/Los_Angeles`). No real accounts, payments, bookings or broadcasts were changed. External map/font requests were blocked in the capture pass, so screenshots can use fallback fonts and do not validate remote embeds.
- Public landing/auth/recovery/MFA/privacy, booking-step variants and the terminal TV page were reviewed in source; they were not included in the 236 new route captures. The report fixture has an empty dataset; populated report export/filter issues below are source findings. Main capture used mostly small datasets, so it does not establish large-directory performance or multi-page correctness.
- Evidence is local under `.audit/ui-review-20261024/`: `source-inventory.json`, `observations.json`, `grid-state.json`, `screens/`, and focused tablet screenshots. These generated artifacts are ignored by Git. Temporary audit runners reused the existing fixture setup; original verification scripts were not modified. Initial attempts failed because Windows blocked preview/browser child processes; the completed pass was rerun after enabling the local processes.

## Existing improvements to preserve

The older October 14 review is historical evidence. Its following concerns are already addressed in current source and should not be reported as newly missing:

- Home puts the upcoming booking before search/board/forecast and uses shared payment guidance.
- Queue freshness is visible in Ticketing and Boarding.
- Admin actual trips and daily schedules have separate view controls.
- Passenger entry already has compact trip context, collapsed reminders and sticky actions.
- Shared readable status labels are used by tickets and other screens, although tone mapping still differs.
- Operational port/vessel directories have active/archive handling and retained-history guidance.
- Admin's Port Display shortcut uses a monitor icon; staff mobile back controls are visible in the current Boarding capture.
- Broadcast search/global sorting is implemented over collected pages. The remaining issue is scalability, not the former claim that search only scans one page.

## Suggested implementation order

1. **Correctness:** G1 table state and C1 missing payment-method copy. Validate actual breakpoint behavior and paid/unpaid metadata combinations.
2. **Shared grid usability:** G2–G6 typed columns, compact toolbar/count scope, mobile card hierarchy and tablet sizing. Migrate callers incrementally.
3. **Role-specific recovery:** saved-traveler field errors, shortened Boarding intro, restored Ticketing discovery context and consistent status presentation.
4. **Reports and scale:** export-scope contract and backend search/order where needed. These require explicit functional verification in addition to visual checks.
5. **Polish and maintainability:** readability, selective desktop expansion, CSS ownership and smaller view modules.
